# Alice Station Mini — root и управление с Linux

Практический комплект заметок и исходных примеров для **Яндекс Станции Мини
первого поколения (YNDX-0004)** и ПК с Arch Linux / Hyprland. Содержит материалы
по существующей архитектуре Alice Commander, голосовым сценариям, RGB и Android.
Штатные ASR, TTS и голос Алисы остаются у Яндекса.

**Статус проекта:** код в `reference/` — обезличенная копия работающей установки,
предназначенная для изучения и адаптации, а не универсальный установщик. На другой
машине необходима настройка путей, пакетов, интеграций, прав и оборудования.
Не копируйте пользовательские сервисы поверх работающей конфигурации без проверки.

## Модель и безопасность

Подтверждённая модель — **YNDX-0004, yandexmini, шесть LED**. Не переносите
адреса устройств, имена сервисов и разрешения на другие модели по аналогии.
Уже полученный root, Homebrew или BetterYAM не переустанавливаются просто для
настройки Commander. Не делайте factory reset и не перепрошивайте чужую модель.

Рабочая система должна оставаться доступной без компьютера. Не перехватывайте
трафик Яндекса, не подменяйте TLS/ASR/TTS, не запускайте вторую запись
микрофона и не меняйте ALSA или wake-word модель. Командные API должны быть
доступны только локально, с авторизацией; не публикуйте их в интернет.

Перед изменениями отдельно сохраните и проверьте резервные копии, права доступа
и контрольные суммы. Личные ADB-ключи, дампы прошивки, `.storage` Home Assistant,
токены, журнал диалогов и ID устройств не должны попадать в публичный Git.

## Root на Mini 1

Метод и приложение **Station Mini Root 0.3.12** поддерживаются отдельным
автором: [оригинальный репозиторий](https://github.com/hertebeznat-cell/alice-station-1-mini-root)
и [описание метода](https://github.com/hertebeznat-cell/alice-station-1-mini-root/blob/main/docs/METHOD.md).
Оригинальный код не включён в этот репозиторий: его лицензия ограничивает
распространение. Перед использованием изучите оригинальные условия и README.

Для ещё не рутированной Mini 1 общая последовательность в оригинальном проекте:

1. Подтвердите модель YNDX-0004, изучите риски и обеспечьте надёжное питание и
   USB-кабель передачи данных. Не используйте инструкцию для других моделей.
2. Установите/запустите приложение из официального релиза и подготовьте его
   зависимости согласно инструкции автора. Программа использует доступный TPL/
   U-Boot и проверяет состояние устройства; это не универсальный root для всех
   выпусков прошивки.
3. Дождитесь создания полного **собственного** бэкапа раздела system и
   сохраните рабочую папку и ADB-ключ в защищённом месте. Не используйте чужой
   образ или бэкап от другого устройства.
4. Изучите предупреждения программы: операция root записывает изменённый system
   и влияет на распознанные OTA-механизмы. Проводите её только после явного
   согласия владельца; проверяйте полный обратный readback и SHA-256, как описано
   автором. Потеря питания/кабеля во время записи может вывести устройство из строя.
5. После загрузки отдельно подтвердите идентичность, `uid=0` и работу штатной
   Алисы. Дальнейшая установка Homebrew или BetterYAM выполняется лишь при
   необходимости и по документации конкретных версий.
6. Для восстановления используйте **свой** сохранённый бэкап и оригинальную
   инструкцию; возврат бэкапа восстанавливает его исходное состояние OTA.

Если root уже есть, этот этап пропускается. Проект не распространяет прошивки,
готовые модифицированные образы, ключи и дампы устройств.

## Архитектура Commander

```text
Фраза → штатная Алиса → сценарий Яндекса → Yandex.Station / Home Assistant
→ yandex_scenario → локальный Unix socket → фиксированный Command Router
→ Desktop Agent или один RGB-координатор → BetterYAM → кольцо Mini 1
```

- `reference/alice-commander/` — Python asyncio agent, router, CLI, веб-панель,
  модуль голосовых событий и Phone Control.
- `reference/alice-commander/integrations/homeassistant/` — отдельный узкий
  HA-компонент, пример конфигурации, pinned compose и patch метаданных событий.
- `reference/pc-notifications/` — единственный координатор RGB и его локальная
  панель. Не запускайте второй независимый LED-контроллер.
- `reference/alice-sounds/` — генератор собственной демонстрационной звуковой
  темы. Аудиофайлы Яндекса и резервные копии не распространяются.

На исходной установке Commander работал в `systemd --user`, после запуска
графического сеанса; Dashboard доступен на `127.0.0.1:8878`, отдельная панель
RGB — на `127.0.0.1:8877`, HA — на `127.0.0.1:8123`. Ваши настройки могут
отличаться. Не публикуйте эти интерфейсы наружу. Путь события не передаёт
свободный распознанный текст в shell: допускаются только зарегистрированные ID.

### Подготовка на новой машине

1. Установите Python 3 и пользовательский systemd; для рабочих команд нужны
   подходящие вашей системе Hyprland, терминал, браузер, `wpctl`, `playerctl` и
   при необходимости редактор. Проверьте доступность BetterYAM и Homebrew на
   реальной колонке. Их версии/API отличаются между моделями.
2. Скопируйте `reference/alice-commander` и `reference/pc-notifications` в
   рабочую директорию только после изучения исходников. Создайте закрытые
   `data/`, `data/voice/`, `data/phone/` и RGB `data/` с правами 0700.
3. Используйте `config/*.example.json` и `pc-notifications/config.example.json`
   как шаблоны. Задайте свои пути и адрес BetterYAM, разрешённый рабочий каталог
   и заранее проверенную команду тестов. Настройки примера содержат фиктивные
   значения: `YOUR_USER`, `YOUR_MINI_ENTITY` и демонстрационный IP не работают.
4. Изучите реальные команды и пути в `agent/desktop.py`, `integrations/phone/`
   и systemd unit-файлах. Например, Kitty, Code OSS, hyprlock и Omarchy в коде
   привязаны к исходному окружению и должны быть заменены только на проверенные
   эквиваленты. Не запускайте неподтверждённые сценарии на продуктивной системе.
5. Прочитайте `integrations/homeassistant/compose.example.yaml`: порт 8123 на
   хосте привязан к loopback, контейнер без privileged и Docker socket. UID/GID,
   часовой пояс, версия HA и тома требуют адаптации. Никогда не коммитьте `.storage`.
6. В Home Assistant установите [Yandex.Station](https://github.com/AlexxIT/YandexStation)
   согласно его инструкции и войдите в нужный Яндекс-аккаунт самостоятельно.
   Не передавайте пароль или QR-токен третьим лицам. Компонент Commander требует
   `scenario-identifiers.patch` к соответствующей версии Yandex.Station; проверьте
   применимость патча и его лицензию, затем настройте `settings.example.json`.
   Версия upstream может поменяться: проверяйте событие и поля заново.
7. Сначала проверьте локальные CLI/API, токены, CSRF и права сокета. Далее в
   «Доме с Алисой» создайте один тестовый сценарий с уникальной фразой и одним
   действием своей Mini: «Ответить на вопрос или выполнить команду» →
   `Ничего не делай`. Сопоставьте имя с фиксированным ID в `voice/scenarios.py`.
   Подтвердите настоящий UUID, событие, выполнение и физический результат.
8. Только после испытаний настройте свои user units и запуск после графического
   сеанса. Пример запускает существующий контейнер HA через Docker socket; он
   не подходит, если контейнер или имя отличаются. Не запускайте два HA/моста.

Это карта ручной интеграции, а не обещание воспроизводимости на любой системе.
Для развёртывания нужно адаптировать файлы и дополнить отсутствующую личную
конфигурацию; никогда не переносите реальные токены из другой машины.

## Команды и голос

В `commands/registry.py` — фиксированный список системных, мультимедиа, проектных,
информационных и RGB-действий; Phone Control добавляет отдельные ID. Router
отклоняет неизвестные команды и аргументы, использует ограничения частоты и
тайм-ауты. Приложения и разрешённые каталоги надо настроить для вашей системы.

Создание карточки в приложении само по себе не доказывает работу голоса.
Проверяйте отдельно: голосовую фразу, запуск сценария, `yandex_scenario`, UUID,
вызов Router и физический результат. Произвольные фразы/команды из сети не
исполняются. На демонстрационной установке подтвердились восемь сценариев Android;
результаты другого устройства или плеера необходимо проверять заново.

## RGB и звук

Кольцо обслуживает только существующий RGB-координатор, который ограничивает
эффект двумя секундами и возвращает управление штатной индикации. Пока надёжный
LED ownership не подтверждён, автоматический Rainbow Wake оставлен выключенным:
предыдущая физическая проверка показала конфликт и мерцание. Ручной preview не
является доказательством запуска от слова «Алиса».

Замена звуков требует отдельных резервных копий и проверки именно этой прошивки:
файлы могут находиться в системном разделе, формат и выбор конкретного события
зависят от версии Quasar. Оригинальные файлы и голос сюда не включены. Не
перепрошивайте колонку и не меняйте аудиоконфигурацию ради эффекта. Проверяйте
таймеры, громкость и речь физически; предусмотрите точный возврат своих файлов.

## Android

Используйте официальные [KDE Connect](https://kdeconnect.kde.org/),
[scrcpy](https://github.com/Genymobile/scrcpy) и [ADB](https://developer.android.com/tools/adb).
Сопряжение подтверждает владелец телефона. Важно проверить тип устройства и
сохранить только один разрешённый ID; Яндекс Станцию нельзя принять за телефон.

Для Android 11+ включайте штатную беспроводную отладку только по желанию и
используйте pairing-код на телефоне, не отправляя его в чат. ADB 5555 не нужен.
`scrcpy` запускается лишь по команде и останавливается только собственный
процесс. Ссылку и файл пользователь выбирает и подтверждает локально; секреты и
скрытые файлы не передаются. Уведомления не сохраняются в журнале. Блокировка
телефона доступна только при подтверждённой поддержке официальным API;
не заменяйте её произвольной ADB-командой. Поиск телефона в нашей установке
отключён владельцем.

## Проверки и откат

Для текущего экземпляра доступны `alice-commander status`, `commands`,
`voice status`, `doctor`, `disable`, `enable`; Phone Control предоставляет
`alice-phone status`, `connect`, `mirror`, `mirror-stop`, `disconnect`,
`disable`, `enable`. Эти команды появятся только после адаптации и установки CLI.

Выполните модульные тесты из каталога Commander (`python3 -m unittest discover
-s tests -v`) после установки зависимостей и конфигурации. Отдельно проверяйте
физические действия и системный перезапуск. Не считайте HTTP 200 или
`accepted=true` доказательством действия. Ранее в исходном окружении прошло 50
тестов, но на новой системе этот результат нужно подтвердить заново.

Для отката сохраните свои версии unit/config и точные контрольные суммы до
установки. Остановка пользовательских служб Commander и Phone Control должна
оставлять BetterYAM, Homebrew, штатную Алису, оригинальный голос, аккаунт HA и
другие устройства нетронутыми. Не удаляйте общие ADB-ключи. Примеры
восстановления в исходниках предполагают локальные backups, которых здесь нет;
не запускайте их без собственных проверенных резервных копий.
